# 旧系统功能核对（2026-11-19）

依据提供的 Junyang-UI、Junyang-Projects、Junyang-Finance、Junyang-Files 和 Junyang-Core 仓库，结合新版代码核对。此记录是本轮已核实的差异，不代表已经逐项验证所有功能。

## 项目列表

- 旧版投标项目查询全部项目，中标项目按 `bidStatus=已中标` 查询；默认按 `createdAt` 降序，每页 25 条。新版已按此口径查询，并支持切换每页条数。
- 投标和中标列表补回旧版每页 2 条的分页选项。隔离数据库验证两类列表分页、中标状态、投标方式和开完工日期组合；未单独验证浏览器分页交互或生产组合筛选。
- 旧版投标页有开标日期、中标公司、投标公司、模糊搜索、中标状态及中标方式；中标页有开工日期、完工日期、中标公司、模糊搜索和项目编号。新版包含这些筛选，另外保留项目状态筛选。
- 旧版中标公司为远程选择具体公司并匹配公司标识和名称，投标公司为名称搜索；新版已对齐这两种筛选。项目详情的中标公司选项现使用项目权限读取。
- 旧版模糊搜索匹配 `name/namePY/person/purpose/tags/notes/title/todo/issuer`，投标页另匹配投标人；新版已补齐这些字段，另保留投标公司、项目描述和数字编号的搜索，结果因此可能比旧版多。
- 旧版提供项目名称同步到交易、收票和开票。新版同步由服务端使用项目当前名称执行；旧版接口要求登录，新版额外要求项目列表访问权限。

## 其他模块已确认差异

- 公司管理：新版已增加列表、新增、编辑和软删除，均直接访问数据库；旧系统不会识别新版的删除标记。
- 上传文件：图片和 PDF 可侧栏预览，其他格式可下载；项目、财务及文件管理的单文件上限为 100 MB，人员图片与社保凭证上限为 10 MB。
- 项目详情：已拆分项目信息、发票和文件权限；交易模块的项目权限与财务权限差异仍需逐项核对。
- 人员证件、考试、账户删除接口中仍有管理员判断，需要逐项对照旧接口权限和用户角色后验证；不应仅以旧版前端是否显示按钮判定权限。
- 拟投项目、预算和证件管理等旧路由是否仍用于生产，需要继续核对用户当前菜单和数据，不能根据仓库中存在路由就认定已完整接入。

## 测试边界

项目筛选、分页、项目权限和名称同步已使用隔离数据库及模拟账号测试；真实生产数据只读核对过数量和默认排序。浏览器连接旧系统超时，因此本轮尚未完成旧、新页面的实时逐屏交互及全模块逐项验收。

## 独立运行与软删除

- 新登录和权限验证可通过 MySQL 独立运行；默认独立模式下旧会话会要求重新登录，仅显式配置旧认证模式时才兼容旧 Core。项目、财务、文件管理附件以及人员图片与社保凭证由新版直接访问对象存储。旧格式人员图片须先通过迁移脚本复制到 OSS 并更新关联；生产检查当前为零条。数据库连接和 SSH 隧道仍是运行依赖。
- 账号、角色、权限目录、公司列表及新增/编辑、人员列表与基本信息读取/新增/编辑、工资、社保、证件和考试列表已改为新版直连数据库。管理角色按管理员处理，其他角色的菜单和操作按权限过滤。
- 项目附件与收票转账记录移除时保留归档。公司软删除保留原记录并记录操作者；证件与考试已增加软删除；人员图片与角色已增加软删除；尚需设计兼容分页和旧系统数据的软删除、恢复及审计方案。
- 2026-11-19 票据概览实测：空条件收票约 6136 条，数据库聚合一次约 80–100ms，但同一查询也发生约 11 秒延迟和数据库连接选择超时；不应仅凭此添加索引。应先排查生产 MongoDB 和 SSH 通道的间歇性延迟。

## 本轮财务与人员核对

- 财务列表补充了旧系统的发票序号、工程编号、税率、对账日期、收付款户名和渠道等字段，并在详情中补充已有的票据信息；其余编辑字段和筛选仍需逐项验证。
- 人员列表改为数据库查询。使用生产只读数据对照旧接口，人员总数和首页 ID 顺序一致（179 条、每页 20 条）。
- 角色与公司变更在隔离环境验证，生产环境只进行读取验证，未创建或修改业务记录。

- 人员明细只读对照：工资、社保、证件、考试的首页总数和 ID 顺序与旧接口一致；当前生产样本中工资、社保和考试为空，证件有 1 条且字段一致。

- 财务列表默认每页 25 条、按创建时间倒序；只读核对交易、收票、开票三类数据总数和首页 ID 顺序一致（分别为 9914、6136、4030 条），本次请求约 1.3 秒、166 毫秒、162 毫秒；这不能排除此前观察到的间歇性慢查询。

- 人员基本信息新增和编辑已迁移至数据库事务，保留新增物品清单、关联同名考试以及修改姓名同步证件和考试的旧行为；模拟测试覆盖无权限、重复姓名和不存在的人员。真实员工的五个编辑字段与旧接口只读比对一致，生产写入尚未验证。

- 员工名单补充入职时间范围和社保缴纳方式筛选，查询按钮统一提交。与旧接口用真实数据只读核对：入职日期范围 15 条、公司全缴 1 条、组合条件 1 条，数量和首页顺序一致。社保筛选受社保查看权限控制。

- 员工编辑补充固定工资和资料费提成，读写需工资查看和修改权限；只修改基本资料时不更新工资。生产记录只读对照工资、提成一致；模拟接口覆盖有权、无权和空值，尚未做生产写入。

- 项目、财务和文件管理附件使用新版生成的 OSS 预览、下载签名与限时上传策略。隔离环境覆盖上传及预览，生产历史图片预览返回 200、下载返回有效跳转；生产存储账号不允许删除测试对象，故没有执行新的生产上传测试。

- 人员图片与社保凭证新增文件改为存入 OSS 并直接读取，社保凭证继续更新缴纳日期和状态。生产数据库目前旧格式图片、凭证关联均为 0；隔离测试覆盖新格式上传与预览。历史文件须先运行迁移脚本。OSS 测试对象删除权限不足，未进行生产写入验证。

- 新认证支持旧普通账号密码和 Django PBKDF2 超级管理员密码，管理角色视为管理员，密码或启用状态变化会使新会话失效。15 个启用的普通账号权限与旧接口逐项只读比较一致；真实管理员在旧 Core 不可用的测试进程中登录并读取人员和账号列表成功。旧会话在过渡期仍依赖旧 Core。

- 公司软删除通过独立标记表保留原记录与关联，已删除公司从公司列表和财务新增选择中隐藏；隔离测试覆盖删除、重复删除、已删除编辑与权限，生产只验证空标记表及列表数量，未删除真实公司。

- 证件批量删除和考试删除采用独立软删除标记，列表过滤，已删除记录不能继续编辑或批量年审。隔离测试覆盖权限、重复删除和并发版本检查；生产只验证列表数量，未删除真实记录。旧系统不识别新版标记。

- 人员资料图片删除保留原文件和原记录，使用删除标记隐藏列表并阻止预览；隔离测试覆盖权限、归属、重复删除及删除后的列表和预览，生产环境只验证读取，没有删除真实图片。

- 角色软删除保留角色及权限，并拒绝删除仍绑定账号的角色；删除后不允许再分配或编辑。隔离测试覆盖权限、绑定限制、重复删除与已删除角色分配；生产只验证列表数量，未删除真实角色。旧系统不识别删除标记。

- 公司管理补充按名称、简称、法人或社会信用代码查询，并提供旧版的分页条数选项；生产只读验证“浚杨”和特殊字符查询与数据库结果一致。旧页面本身没有搜索框。

- 项目详情的收票、开票和票据概览对具备 `project_bill_view` 的账号开放，接口强制按项目 ID 查询；未具备财务权限的账号不显示财务编辑操作，且不能查询全局票据或交易。隔离测试覆盖两类票据及汇总访问边界。

- 交易概览按旧版展示总支出、总收入、总合计以及已/未对账各三项；未识别对账状态不计入这九项，与旧版相同。隔离数据覆盖收支、状态和筛选，生产选取一个项目按旧聚合口径只读比对一致。

- 票据概览按公司分组的收票与开票，生产数据按旧聚合算法对比，分组数和金额一致（分别 24 组、23 组）；切换到或离开抵扣月份时清空日期范围，隔离浏览器已验证。

- 文件管理增加一级/二级分类、归属、关联、标签、年审和状态筛选，以及备注、生效/到期日期等列表字段；旧分类与人员公司数据用于筛选选项。隔离测试验证组合筛选和参数校验，生产只读比对一个分类及年审组合的数量一致。文件元数据编辑、类别管理等仍需继续迁移。

- 文件管理对照旧源码补充文件名称、分类、归属、关联、标签、备注、日期、年审及状态编辑，列表显示归属和关联；编辑与删除分别要求文件查看及上传/删除权限。删除使用原有 `enabled=false` 软删除并保留对象，附件接口对已删除记录返回不存在。隔离数据库测试覆盖编辑、权限、非法字段和日期、并发冲突、软删除及删除后访问；未对生产数据执行写入。分类管理和实际浏览器逐项操作仍待核对。

- 文件分类增加一级和二级分类的新增、删除；一级分类标记删除，二级分类保留删除记录，历史文件的分类字段和对象保持不变。文件列表增加生效日期、到期日期表头排序，分页选项与旧版一致。隔离测试覆盖分类增删、权限、重复操作、排序参数与软删除；隔离浏览器验证侧栏和新增二级分类。生产环境未进行分类写入，旧系统不识别新分类删除标记；并发新增同名分类尚无数据库唯一约束。

- 公司筛选隔离测试覆盖同名不同公司、公司更名、非法标识和项目权限访问；尚未逐个比较生产公司的筛选结果。

- 财务列表和交易概览按旧版支持选择具体项目、公司，按关联标识查询而非名称包含匹配；无财务权限的项目收开票仍按原项目范围并使用公司名称筛选。列表提供旧版分页条数（2、25、50、100、200、300、400）。隔离数据覆盖同名公司、分页、汇总以及项目权限边界，浏览器验证项目选择与查询；其他旧版财务筛选组合和编辑功能仍需逐项核对，生产数据尚未逐项比对。

- 财务筛选支持同时设置交易/开票、对账、抵扣和做账日期范围；列表与汇总使用相同条件，并兼容原有单日期参数。隔离数据覆盖多个日期交集及汇总结果，包含北京时间结束日和无效范围；浏览器确认收票页显示独立日期范围。尚未逐项对照生产数据或验证所有旧版财务操作。

- 收票、开票增加复制操作。依据旧版复制基础字段、清空金额和对账及附件信息；新版先在侧栏确认新票号和金额再保存，避免旧版开票复制可能沿用唯一票号导致冲突。隔离浏览器分别验证两类票据的预填与保存；未对生产票据写入。项目或公司已被删除的历史记录复制时需要重新选择有效关联。

- 交易、收票、开票列表增加当前筛选条件下的全部记录合计，与分页无关；交易金额沿用旧版只汇总存在收支方向的记录，收开票显示不含税、税额和含税金额。隔离测试覆盖分页、缺少方向和组合筛选，浏览器验证收票表格展示；生产只读对照三类无筛选金额合计一致，本次聚合约 133/69/62 毫秒，仍不能排除连接抖动。数据库隧道先前中断，已重新建立。

- 默认认证不再依赖旧 Core；独立模式下旧令牌返回 401 并引导重新登录，显式 legacy 模式保留过渡兼容。隔离测试覆盖旧 Core 不可用时的登录、权限、旧会话失效和旧模式回归；历史旧格式人员图片仍需迁移。

- 未对账交易、收票和开票的编辑抽屉支持更换项目与公司；未变更的关联保持原始值，修改时验证关联存在并检查记录版本。隔离测试覆盖三类记录、权限、无效关联与冲突，隔离浏览器验证收票项目变更；生产未执行写入。旧版票据序号和对账日期编辑、已对账票据可编辑的差异仍待核对。
